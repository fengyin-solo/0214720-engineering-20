# 台球俱乐部管理系统

## How to Run

```bash
# 构建并启动所有服务
docker-compose up --build -d

# 查看运行状态
docker-compose ps

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

### 用户端可复现基线（开发 / 构建 / 端口 / 容器）

用户端（`frontend-user`）的启动、构建、环境变量、端口与容器约束已固化为脚本基线，详见
[`frontend-user/BASELINE.md`](./frontend-user/BASELINE.md)。对缺少依赖、配置缺失、端口占用、
构建失败、产物缺失均有统一退出码与提示；检查/冒烟结束后不残留服务，不改写业务源码。

| 场景 | 命令 | 说明 |
|------|------|------|
| 只读基线检查 | `cd frontend-user && npm run check:dev`（生产：`npm run check:prod`） | 依赖与平台匹配、环境变量、端口 |
| 开发启动（固定 8080，占用即失败） | `npm run dev` 或 `bash scripts/dev.sh`（冒烟：`npm run dev:smoke`） | 退出自动回收进程 |
| 生产构建 + 产物/HTTP 冒烟 | `bash scripts/build.sh --verify`（npm：`npm run build:verify`） | 构建失败退出码 5，产物缺失 6 |
| 本地预览产物（8090） | `bash scripts/preview.sh` | 退出自动回收进程 |
| 容器一键构建/验证/停止 | `bash scripts/container.sh up` / `verify` / `down` | 8081→80，含 HEALTHCHECK |

端口基线：**dev 8080**、**本地 preview 8090**、**容器 8081→80**（compose 固定映射）。
统一退出码：`2` 缺少依赖/平台不匹配、`3` 端口占用、`4` 配置缺失、`5` 构建失败、`6` 产物缺失/入口检查失败、`7` 服务未就绪。

> 现有命令 `npm run dev` / `build` / `preview` / `test` 与默认 Mock 数据继续可用，基线脚本仅做检查与包装。

### ARM架构兼容性验证

本项目使用的基础镜像均支持多架构（AMD64/ARM64）：

```bash
# 1. 验证基础镜像 ARM 兼容性
docker pull --platform linux/arm64 node:20-alpine
docker pull --platform linux/arm64 nginx:1.25-alpine

# 2. 验证镜像可运行
docker run --rm --platform linux/arm64 node:20-alpine node --version
docker run --rm --platform linux/arm64 nginx:1.25-alpine nginx -v

# 3. 在 Apple Silicon Mac 上构建运行
docker-compose up --build -d

# 4. 验证构建后的镜像架构
docker inspect billiard-frontend-user | grep Architecture
```

### 跨平台构建命令

```bash
# 指定平台构建
docker build --platform linux/arm64 -t billiard-user:arm64 ./frontend-user

# 多架构构建（需要 buildx）
docker buildx create --use
docker buildx build --platform linux/amd64,linux/arm64 -t billiard-user:latest ./frontend-user
```

## 数据说明

### 模拟数据声明

本项目当前使用**前端模拟数据（Mock Data）**，无需后端服务即可运行演示。

### 模拟数据范围

| 模块 | 数据内容 | 数量 |
|------|----------|------|
| 用户 | 测试账号、用户信息、积分记录 | 1个账号 |
| 球桌 | 球桌列表、预约时段 | 6张球桌 |
| 课程 | 课程列表、教练信息、课程大纲 | 4门课程 |
| 赛事 | 赛事列表、报名信息 | 5场赛事 |
| 商品 | 商品列表、分类信息 | 8件商品 |
| 订单 | 预约记录、购买订单 | 动态生成 |

### 模拟数据限制

1. **数据不持久化**：刷新页面后，新增的订单、预约等数据会丢失
2. **单用户模式**：仅支持一个测试账号登录
3. **无真实支付**：支付流程为模拟，不涉及真实交易
4. **固定数据**：球桌、课程、商品等基础数据为固定值
5. **无实时更新**：赛事状态、库存等不会自动更新

### 切换真实API

修改环境变量即可切换到真实后端：

```bash
# .env.production
VITE_USE_MOCK=false
VITE_API_BASE_URL=https://api.your-domain.com
```

## 环境变量配置

### 配置文件说明

| 文件 | 用途 | 说明 |
|------|------|------|
| `.env.example` | 配置模板 | 包含所有可配置项及说明 |
| `.env.development` | 开发环境 | 本地开发使用 |
| `.env.production` | 生产环境 | Docker构建使用 |
| `.env.local` | 本地覆盖 | 不提交到Git，优先级最高 |

### 环境变量详解

| 变量名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `VITE_APP_TITLE` | string | 台球俱乐部 | 应用标题，显示在浏览器标签页 |
| `VITE_USE_MOCK` | boolean | true | 是否使用模拟数据。`true`使用前端Mock，`false`调用真实API |
| `VITE_API_BASE_URL` | string | /api | API基础地址。模拟模式下无效，真实模式下配置后端地址 |
| `VITE_LOG_LEVEL` | string | info | 日志级别：`debug`/`info`/`warn`/`error` |

### 配置示例

```bash
# 开发环境 - 使用模拟数据
VITE_APP_TITLE=台球俱乐部(开发)
VITE_USE_MOCK=true
VITE_LOG_LEVEL=debug

# 生产环境 - 连接真实后端
VITE_APP_TITLE=台球俱乐部
VITE_USE_MOCK=false
VITE_API_BASE_URL=https://api.billiard-club.com
VITE_LOG_LEVEL=warn
```

## 项目介绍

基于 Vue 3 的台球俱乐部管理系统用户端，包含 **6个核心页面**：

| 页面 | 路径 | 功能 |
|------|------|------|
| 首页 | / | 俱乐部介绍、服务展示 |
| 球桌预约 | /tables | 球桌筛选、在线预约 |
| 教学课程 | /courses | 课程浏览、报名 |
| 赛事活动 | /competitions | 赛事查看、报名参赛 |
| 装备商城 | /shop | 商品购买 |
| 个人中心 | /profile | 用户信息、订单管理 |

> 登录功能以弹窗形式集成在导航栏中，不占用独立页面。

## 技术栈

- Vue 3 + Vue Router 4
- Vite 5
- ESLint + Prettier
- Vitest (单元测试)
- Nginx (生产环境)
- Docker (容器化部署)

## 错误处理机制

### 1. 全局错误捕获
```javascript
// main.js
window.addEventListener('error', (event) => {
  logger.error('Global error', { message: event.message })
})

window.addEventListener('unhandledrejection', (event) => {
  logger.error('Unhandled promise rejection', { reason: event.reason })
})
```

### 2. API请求错误处理
```javascript
// api.js
async function request(url, options) {
  try {
    const response = await fetch(url, options)
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`)
    }
    return { success: true, data: await response.json() }
  } catch (error) {
    logger.error(`API Error: ${url}`, error)
    return { success: false, error: error.message }
  }
}
```

### 3. 用户友好提示
- Toast组件：显示操作结果（成功/失败/警告）
- Modal组件：确认危险操作
- 表单验证：实时输入校验

### 4. 日志级别
| 级别 | 说明 | 示例 |
|------|------|------|
| DEBUG | 调试信息 | API请求详情 |
| INFO | 常规操作 | 页面导航、登录成功 |
| WARN | 警告信息 | 登录失败、权限不足 |
| ERROR | 错误信息 | 网络错误、系统异常 |
